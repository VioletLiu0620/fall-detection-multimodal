# Multimodal Fall Detection for Elderly Home Monitoring

A skeleton-based fall detection system that classifies short video sequences as **fall** or **no-fall** from human pose keypoints. The goal is to distinguish genuine falls (a medical emergency) from ordinary movements that *look* similar in posture, such as lying down or sitting. This repository contains the completed skeleton-only baseline; an audio branch for multimodal fusion is planned as future work (see below).

## Motivation

Fall detection matters most for elderly people living alone, where a missed fall can mean lying injured on the floor with no help arriving. The hard part of the problem is not detecting that a body is horizontal — it is telling apart a person who *fell* from a person who deliberately lay down, since both end up in similar poses. This ambiguity is what motivates a multimodal design: posture alone is often insufficient, and additional signals (such as audio) can help resolve the hardest cases.

## Results

Evaluated on a held-out, deduplicated test set (308 videos):

| Class    | Precision | Recall | F1   |
|----------|-----------|--------|------|
| Fall     | 0.91      | 0.89   | 0.90 |
| No Fall  | 0.92      | 0.93   | 0.92 |
| **Accuracy** |       |        | **0.91** |

Recall on the *fall* class (0.89) is the metric of primary interest, since a missed fall (false negative) is far more costly than a false alarm in a safety system.

## Approach

**Data.** The [FallVision dataset](https://doi.org/10.7910/DVN/75QPKK) provides masked (pose-landmarked) videos with per-frame keypoint CSVs generated by YOLOv7-Pose (17 COCO body landmarks per frame). This project uses the keypoint CSVs rather than raw video, making the pipeline lightweight enough to train on a laptop.

**Preprocessing pipeline** (per video):
1. **Deduplication** of skeletons within a frame — some frames contained multiple detected skeletons (a real person plus low-confidence phantom detections); the highest-average-confidence skeleton per frame is kept.
2. **Reshaping** the long-format CSV into a `(frames, 17, 3)` array (17 joints, each with x, y, and detection confidence).
3. **Resampling** every video to a fixed 64 frames via linear interpolation, handling variable-length and missing-frame sequences uniformly.
4. **Normalization** — each skeleton is centered on the mid-hip (position invariance) and scaled to a roughly unit range for stable training.

**Model.** A 2D convolutional network treats each sequence as a `(3, 64, 17)` "image" — 3 channels (x, y, confidence), 64 frames as height, 17 joints as width — so filters learn spatio-temporal motion patterns across frames and neighboring joints. Two convolutional blocks, max pooling, dropout, and a linear classifier.

**Regularization.** On the deduplicated dataset, the model overfit; this was addressed with input scaling, dropout, and on-the-fly Gaussian-noise augmentation of joint coordinates during training (following common practice for skeleton action recognition under limited data), which reduced the train/test gap from ~12 points to ~3.

## Key finding: data leakage

Early results showed ~98% accuracy. Investigation revealed this was inflated by **severe file-level duplication** in the downloaded dataset: of 5,440 keypoint files, only 1,539 were unique by MD5 content hash (~72% duplicates), with identical files distributed across multiple folders. Under a random train/test split, exact-duplicate videos appeared in both sets, so the model was partly evaluated on data it had trained on.

Deduplicating by content hash and re-evaluating on genuinely unseen data gave the honest result reported above. The dataset paper describes the videos as distinct and does not mention duplication; the cause is unclear, but the files were byte-identical. This finding is the difference between a misleading 98% and a trustworthy 91%.

## Limitations

- **Possible subject leakage.** The dataset provides no subject identifiers, so a subject-independent split was not possible. The same individual may appear in both training and test sets, so metrics may still be optimistic relative to performance on entirely unseen people. Because this applies equally to any model trained on this data, *relative* comparisons (e.g. against a future multimodal model) remain valid.
- **Limited data.** After deduplication, ~1,539 unique videos remain, which constrains achievable performance and makes regularization essential.
- **Demographic skew.** The source dataset is heavily skewed toward younger and male participants, which may limit generalization to the elderly target population.

## Future work

- **Audio branch (multimodal fusion).** Error analysis showed the model's mistakes concentrate on a small number of genuinely ambiguous cases (deliberate movements resembling falls, and gentle falls resembling lying down). Audio cues (impact sounds, distress vocalizations) directly target this ambiguity. The plan is a separately trained audio classifier fused with the skeleton model via late fusion.
- **Graph-based model (ST-GCN).** Graph convolutional networks, which encode the true skeletal structure, are the current standard for skeleton action recognition and could improve on the CNN baseline.
- **Recall-oriented tuning.** Threshold adjustment and class-weighted loss to further raise fall recall, trading precision for fewer missed falls.
- **Synthetic augmentation.** Conditional diffusion models for skeleton generation are a promising direction for expanding the limited dataset.

## Repository structure

- `preprocess.py` — per-video cleaning functions (dedup, reshape, resample).
- `data.py` — dataset assembly: deduplication, processing, train/test split, normalization, augmentation, and PyTorch `Dataset`/`DataLoader` construction.
- `train.py` — model definition, training loop with best-checkpoint saving, and evaluation.

